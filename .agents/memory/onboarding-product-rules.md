---
name: Onboarding product requirements
description: User-required CV-first onboarding, organisation labels and truthful data provenance.
---

Individuals choose “I am working” or “I am a student/graduate” and complete separate step-by-step pages: upload CV, confirm details, answer Holland, see profiling including RIASEC code, then signup to save. A CV RAG agent cooperates with the RIASEC agent.

**Why:** The user explicitly requested this instead of setting up profiles inside the workspace.

**How to apply:** Preserve this order in future onboarding work; extract facts from the CV and ask for missing information rather than inventing it. Provide dummy email identities for walkthroughs.

The user requested “Employee” as the HR portal label and “Educators” as the TVET Centre label, plus dummy accounts for testing both.

**Why:** These are the user's explicit role names, even though Employee can be confused with the individual working segment.

**How to apply:** Use those public labels consistently; do not silently substitute Employer or combine organisation access with individual onboarding.

App facts must use real APIs or datasets, with complete source documentation in Data Sources; features must remain accurate in English (default), BM and Mandarin.

**Why:** The user explicitly required non-hardcoded factual data and accurate three-language coverage.

**How to apply:** Distinguish real-time APIs from periodically released datasets; label demo data and derived results honestly and document source versions, freshness and limitations.
